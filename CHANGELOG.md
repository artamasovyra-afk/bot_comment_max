# Changelog

All notable changes to this project will be tracked here.

## [Unreleased]

## [0.1.25] - 2026-05-12

### Fixed

- Исправлено первичное подключение нового канала новым пользователем, который ещё не является `channel_admin`.
- Создание заявки больше не зависит от предварительного появления пользователя в админке: новый пользователь проходит через `Начать` → принятие условий → пересылку поста из канала.
- Исправлена обработка `bot_started` для новых пользователей, чтобы приветствие и принятие условий работали сразу после кнопки `Начать`.
- Улучшена обработка заявок, когда MAX не присылает `sender.user_id` или не удаётся автоматически проверить права заявителя в канале.
- Добавлены понятные ответы пользователю и reason-коды в логах для отказов при создании заявки.

## [0.1.24] - 2026-05-12

### Fixed

- Исправлена обработка пересланных постов канала в диалоге с ботом, когда MAX не присылает `sender.user_id` в `message_created`.
- Бот теперь восстанавливает пользователя по `dialog_with_user` и не обрывает создание заявки на подключение канала молча.
- Добавлено диагностическое логирование для forwarded-сообщений и игнорируемых `update_type`, чтобы быстрее находить обрывы в pipeline подключения канала.

## [0.1.23] - 2026-05-08

### Added

- В проект добавлены `black` и `isort` с конфигурацией в `pyproject.toml`.

### Changed

- README обновлён командами форматирования и проверки стиля Python-кода.
- `scripts/check.sh` теперь запускает `black --check .` и `isort --check-only .`.
- Большой файл `bot.py` временно исключён из автоформатирования и style-check, чтобы не создавать огромный diff в этой задаче.

## [0.1.22] - 2026-05-08

### Added

- В `requirements.txt` добавлен `pytest` для локального запуска unit-тестов.
- Добавлена папка `tests/` и базовый набор unit-тестов для безопасных функций без MAX API.

### Changed

- README обновлён инструкцией по запуску `pytest` и описанием минимального тестового покрытия.

## [0.1.21] - 2026-05-08

### Added

- Добавлен явный файл `requirements.txt` для воспроизводимой подготовки Python-окружения.
- В README добавлены пошаговые инструкции по созданию `venv`, активации окружения, установке зависимостей, запуску проекта и запуску проверок.

### Changed

- В документации явно зафиксировано, что на текущий момент проект использует только стандартную библиотеку Python и не требует сторонних пакетов из PyPI.

## [0.1.20] - 2026-05-08

### Added

- В WebApp добавлен переход к исходному сообщению по тапу или клику на блок ответа внутри комментария.
- При переходе к исходному сообщению список комментариев автоматически прокручивается к нему и кратко подсвечивает целевой комментарий.
- API комментариев дополнительно отдаёт совместимые поля `replyToCommentId`, `reply_to_comment_id`, `replyPreview` и `authorName` для reply-блока.

## [0.1.19] - 2026-05-08

### Fixed

- Исправлена нормализация URL вложений комментариев: старые изображения теперь автоматически отдаются через актуальный домен `maxcomments.ru`.
- Исправлено отображение изображений в WebApp: fallback `Изображение недоступно` показывается только после реальной ошибки загрузки.
- Исправлено отображение вложений в `/admin` и `/super-admin`: медиа-комментарии больше не сводятся к тексту `Фото/медиа`.
- В админке и супер-админке добавлены компактные превью изображений с открытием полного размера по клику.
- Добавлено диагностическое логирование ошибок раздачи и загрузки изображений.

## [0.1.18] - 2026-05-08

### Changed

- Выбор реакций перенесён из кнопки `+` в меню действий комментария.
- Кнопка добавления реакции больше не отображается в пузыре комментария.
- На мобильных устройствах меню действий открывается долгим тапом, на десктопе — правым кликом или кнопкой `⋯`.
- В комментарии отображаются только уже поставленные реакции и их счётчики.
- В меню комментария добавлены действия `Копировать` и `Скопировать ссылку`.

## [0.1.17] - 2026-05-08

### Added

- Добавлены реакции эмодзи `👍 ❤️ 😂 🔥 😮 😢` на комментарии в WebApp.
- Добавлена таблица `comment_reactions` с ограничением `UNIQUE(comment_id, user_id)`.
- Добавлен endpoint `POST /api/comments/<comment_id>/reaction` для toggle/replace реакции текущего пользователя.
- API комментариев теперь возвращает счётчики реакций и `myReaction` для текущего пользователя.

## [0.1.16] - 2026-05-08

### Fixed

- Удалён внутренний профиль пользователя из WebApp, добавленный в `0.1.15`.
- Удалён endpoint `GET /api/users/<user_id>/profile`, который использовался только для внутреннего профиля.
- Имя и аватар автора больше не открывают внутреннюю модалку; переход будет включаться только при наличии подтверждённого `profileUrl` MAX.

## [0.1.15] - 2026-05-08

### Added

- Имя и аватар автора комментария стали кликабельными в WebApp.
- Добавлен внутренний профиль пользователя с именем, username, количеством комментариев в канале, датой первого комментария и недавними сообщениями автора.
- Добавлен endpoint `GET /api/users/<user_id>/profile`, который отдаёт безопасные данные профиля в контексте текущего поста и канала.

## [0.1.14] - 2026-05-07

### Fixed

- Исправлено поведение изображений в комментариях: короткий клик или тап теперь открывает изображение в полном размере.
- Меню действий для комментария больше не открывается по обычному тапу на мобильном, а вызывается долгим удержанием или правым кликом.
- Добавлена отмена long press при прокрутке или смещении пальца, чтобы изображения не мешали листать чат.

## [0.1.13] - 2026-05-07

### Added

- Добавлены компактные превью изображений в комментариях.
- Добавлен полноэкранный просмотр изображения по клику с закрытием по кнопке, фону и Escape.
- Добавлена навигация между несколькими изображениями одного комментария.

## [0.1.12] - 2026-05-07

### Added

- Добавлена таблица `comment_read_state` для хранения состояния прочтения комментариев отдельно по пользователю и посту.
- `GET /api/posts/<post_ref>/comments` теперь возвращает `readState`, `targetCommentId` и `hasUnread`.
- Добавлен endpoint `POST /api/posts/<post_ref>/comments/read` для обновления статуса прочтения.

### Changed

- WebApp комментариев при первом открытии прокручивается к последнему непрочитанному комментарию, а если непрочитанных нет — к последнему комментарию.

## [0.1.11] - 2026-05-07

### Changed

- Обновлён текст ответа пользователю после создания заявки на подключение канала.

## [0.1.10] - 2026-05-07

### Fixed

- Исправлена проверка прав бота в канале: MAX отдаёт права редактирования как `edit`/`delete`, теперь они корректно принимаются при создании заявки на подключение канала.

## [0.1.9] - 2026-05-07

### Fixed

- Расширен разбор пересланных постов канала: бот теперь ищет данные канала не только в `message.link`, но и во вложенных payload-ах пересылки.
- Добавлено понятное сообщение пользователю, если пересланный пост не удалось разобрать как пост канала.

### Changed

- Добавлено логирование причин, по которым заявка на подключение канала не создаётся: канал уже подключён, бот не администратор, пользователь не администратор канала или уже есть pending-заявка.

## [0.1.8] - 2026-05-07

### Fixed

- Если админ канала пересылает пост до принятия условий, бот теперь отправляет сообщение с кнопкой `Принять`, а не только текстовую подсказку.

### Changed

- Обновлён текст принятия условий для бота ЦИТ.
- Кнопка принятия условий сокращена до `Принять`, старый текст `Принять и продолжить` оставлен совместимым.

## [0.1.7] - 2026-05-06

### Added

- Новый сценарий подключения канала через заявку: админ принимает условия, добавляет бота администратором в канал и пересылает боту пост из канала.
- Таблицы `user_terms_acceptance` и `channel_connection_requests`.
- Раздел `Заявки` в `/super-admin` с одобрением и отклонением заявок.
- Super-admin API `/api/super-admin/channel-requests`.
- WebApp-only режим привязки канала без обязательного отдельного чата комментариев.

### Changed

- После одобрения заявки заявитель автоматически получает роль администратора канала.
- Автодобавление кнопки комментариев работает для новых постов подключённого канала без проверки автора поста в локальной админке.
- Legacy-команды `/setup_channel` и `/bind_comments CODE` сохранены как запасной способ подключения.

## [0.1.6] - 2026-05-01

### Fixed

- Повторное сохранение администратора канала теперь добавляет выбранные каналы к уже назначенным, а не заменяет весь список.

## [0.1.5] - 2026-05-01

### Fixed

- `/admin` теперь очищает неподходящую старую super-admin cookie и показывает форму входа администратора канала вместо экрана `Доступ запрещён`.

## [0.1.4] - 2026-05-01

### Fixed

- Исправлено падение формы добавления администратора канала в WebView/Safari, когда `event.currentTarget` становился `null` после асинхронного запроса.

## [0.1.3] - 2026-05-01

### Added

- Отдельная панель супер-администратора по адресу `/super-admin`.
- Отдельный вход супер-админа через `SUPER_ADMIN_LOGIN` и `SUPER_ADMIN_PASSWORD`.
- Отдельные super-admin API `/api/super-admin/*`.

### Changed

- `/admin` оставлен только для администраторов каналов с входом по MAX user id.
- Глобальные функции админки перенесены в панель супер-админа.
- Backend-проверки разделяют `/api/admin/*` и `/api/super-admin/*`.
- `MAX_ADMIN_PANEL_TOKEN` остаётся устаревшим и не используется для входа.
- Документация обновлена под две административные панели.

## [0.1.2] - 2026-05-01

### Added

- Разделение ролей админки `super_admin` и `channel_admin`.
- Вход в админку по логину/паролю вместо общего `MAX_ADMIN_PANEL_TOKEN`.
- Создание первого `super_admin` через `MAX_SUPER_ADMIN_IDS`.
- Cookie-сессии админки и смена пароля с хранением пароля только в виде хеша.
- Управление администраторами каналов из раздела `Администраторы`.
- Backend-проверки прав для админских API с ограничением `channel_admin` только своими каналами.

### Changed

- `MAX_ADMIN_PANEL_TOKEN` помечен как устаревший и больше не используется для входа в новую ролевую админку.
- Документация обновлена под роли, логин/пароль и создание первого супер-администратора.

## [0.1.1] - 2026-05-01

### Added

- Переключаемый режим доставки событий `polling/webhook` с webhook-endpoint внутри встроенного HTTP-сервера.
- Автоматическое создание и обновление webhook-подписки MAX через `/subscriptions`.
- Браузерная админка `/admin` для управления каналами, публикациями, привязкой постов и синхронизацией.
- Команда `/setup_channel`, которая создаёт канал в админке и запускает мастер подключения чата комментариев.

### Changed

- `GET /api/healthz` теперь возвращает `delivery_mode`, а сервис читает рабочую версию из файла `VERSION`.
- Продовый `.env` можно перевести на webhook без отдельного внешнего обработчика.

## [0.1.0] - 2026-04-30

### Added

- MAX bot and WebApp comments flow for channel posts with per-post discussion threads.
- Automatic comment button attachment for new channel posts and support for multiple connected channels.
- WebApp chat interface with replies, editing, deletion, notifications, photo attachments, and link blocking.
- GitHub Actions CI/CD deployment to the VPS.
